# Plan to Fix State Management, Router, and CRUD Issues in Trust Accounts

## Current Issues Identified

1. **CRUD Operations Not Working**: 
   - Backend has TrustAccount model and web controller, but API routes return hardcoded JSON
   - Frontend uses fake data instead of API calls
   - Transaction creation shows alert but doesn't persist data

2. **State Management Issues**:
   - Accounts data is hardcoded in component instead of using store
   - Stats are static values instead of dynamic calculations
   - No proper state updates after CRUD operations

3. **Router Issues**:
   - Route configuration appears correct
   - Possible navigation problems after actions (e.g., after creating transaction)
   - May need better error handling for route guards

## Proposed Solution

### Backend Fixes (API Routes)
1. **Add TrustAccount API Controller**
   - Create `app/Http/Controllers/Api/TrustAccountController.php`
   - Implement index, store, show, update, destroy methods
   - Add proper validation and balance calculations

2. **Update API Routes**
   - Replace hardcoded `/trust-accounts` GET route with controller routes
   - Add POST, PUT, DELETE routes for full CRUD
   - Add route for client-specific transactions and balances

### Frontend Fixes (Vue.js + Pinia)
1. **Create Trust Accounts Store**
   - Add `resources/js/stores/trustAccounts.js`
   - Manage accounts state, loading states, errors
   - Implement actions for fetch, create, update, delete

2. **Update TrustAccountsPage.vue**
   - Replace hardcoded data with API calls
   - Implement real transaction creation
   - Add loading states and error handling
   - Update stats dynamically from API
   - Fix navigation after actions

3. **Add Error Handling**
   - Handle API errors gracefully
   - Show user-friendly error messages
   - Implement retry mechanisms

### Additional Improvements
1. **Add Transaction History**
   - Display real transaction history per account
   - Add filtering and pagination

2. **Improve UX**
   - Add confirmation dialogs for destructive actions
   - Show success/error toasts
   - Better loading indicators

3. **Data Validation**
   - Client-side and server-side validation
   - Prevent negative balances
   - Validate transaction types
