# Plan: Fix Tenant-Scoped API Calls in Frontend

## Problem Analysis
The application uses multi-tenancy where API routes are scoped under `/api/tenant/{tenantId}/`. However, the frontend is making calls to `/api/tasks`, `/api/documents`, `/api/cases`, etc., which don't exist. The correct URLs should be `/api/tenant/{tenantId}/tasks`, `/api/tenant/{tenantId}/documents`, etc.

## Root Cause
1. Frontend axios baseURL is `/api`, but routes are actually `/api/tenant/{id}/resource`
2. User data doesn't include tenant_id in API responses
3. Frontend doesn't know which tenant ID to use for API calls

## Solution Steps

### 1. Include tenant_id in User API Response
- Add `tenant_id` to User model API serialization
- Ensure `/api/user` returns tenant_id in response

### 2. Update Frontend Auth Store
- Modify auth store to store tenant_id from user data
- Add tenant_id to state and getters
- Add logic to handle missing tenant_id (though all users should have it per requirements)

### 3. Create Axios Interceptor for Tenant URLs
- Add request interceptor in `resources/js/app.js` to automatically prepend `/tenant/{tenantId}/` to API calls
- Configure interceptor to skip tenant scoping for auth endpoints: `/login`, `/register`, `/logout`, `/user`, `/settings`, `/session-token`

### 4. Update User API Route
- Modify `/api/user` route to return tenant relationship data
- Ensure tenant_id is included in the JSON response

### 5. Handle Edge Cases
- Add error handling for users without tenant_id (though this shouldn't occur per requirements)
- Ensure auth endpoints remain global and accessible without tenant context

## Files to Modify
- `app/Models/User.php` - Ensure tenant_id is included in API responses
- `routes/api.php` - Update `/api/user` route to include tenant data
- `resources/js/stores/auth.js` - Store tenant_id from user data
- `resources/js/app.js` - Add axios request interceptor for tenant scoping

## Testing
- Verify login still works and returns tenant_id
- Check that API calls include tenant ID in URL (e.g., `/api/tenant/1/tasks`)
- Test with multiple tenants to ensure isolation
- Ensure auth endpoints work without tenant scoping
- Verify error handling for missing tenant context

## Implementation Notes
- All users have tenant_id per requirements
- Auth endpoints (`/login`, `/register`, `/logout`) remain global
- Frontend will automatically prepend tenant context to all other API calls
