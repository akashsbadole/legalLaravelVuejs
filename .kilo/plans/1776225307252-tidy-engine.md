# Legal Management System - UI Completion Plan

## Overview
Focus on completing 6 key UI features that have frontend components but lack proper backend API integration. Each feature needs working APIs, data persistence, and real-time synchronization.

## Target Features (UI Exists, Backend/APIs Missing)

### 1. Legal Chatbot
- **Frontend**: Complete UI + Pinia store with mock methods
- **Backend Missing**: `ChatbotController` (routes exist but controller missing)
- **APIs Needed**:
  - `POST /api/legal/chatbot/message` - Send message and get AI response
  - `POST /api/legal/chatbot/conversation` - Create new conversation
  - `GET /api/legal/chatbot/conversations` - List user conversations
  - `GET /api/legal/chatbot/conversation/{id}` - Get specific conversation
  - `PUT /api/legal/chatbot/conversation/{id}` - Update conversation
  - `DELETE /api/legal/chatbot/conversation/{id}` - Delete conversation

### 2. Reports Page
- **Frontend**: Complete UI with charts and data visualization
- **Backend**: `ReportsController` exists but data may be incomplete
- **APIs Needed**:
  - `GET /api/reports` - Overview report data
  - `GET /api/reports/financial` - Financial reports
  - `GET /api/reports/cases` - Case reports
  - `GET /api/reports/export` - Export functionality

### 3. Calendar
- **Frontend**: Complete calendar UI with event display
- **Backend Missing**: Calendar event APIs
- **APIs Needed**:
  - `GET /api/calendar/events` - Get events for date range
  - `POST /api/calendar/events` - Create event
  - `PUT /api/calendar/events/{id}` - Update event
  - `DELETE /api/calendar/events/{id}` - Delete event

### 4. Notifications
- **Frontend**: Complete notifications UI with read/unread states
- **Backend Missing**: Notification CRUD APIs
- **APIs Needed**:
  - `GET /api/notifications` - Get user notifications
  - `PUT /api/notifications/{id}/read` - Mark notification as read
  - `PUT /api/notifications/read-all` - Mark all as read

### 5. Client Portal
- **Frontend**: Complete client dashboard UI
- **Backend Missing**: Client portal APIs
- **APIs Needed**:
  - `GET /api/portal/dashboard` - Client dashboard data (cases, invoices, documents)

### 6. Admin Dashboard
- **Frontend**: Complete admin dashboard UI with system stats
- **Backend Missing**: Admin dashboard APIs
- **APIs Needed**:
  - `GET /api/admin/dashboard` - Admin system statistics

## Current State Analysis
- **Backend**: Laravel 13 with comprehensive models but missing specific controllers/APIs for the 6 target features
- **Frontend**: Vue 3 + Pinia with complete UI components for all 6 features, using mock data/stores
- **Database**: Multi-tenant with legal references and comprehensive schema
- **Authentication**: Sanctum with roles (admin, attorney, paralegal, client)

## Implementation Plan

### Phase 1: Legal Chatbot Backend Implementation

#### 1.1 Create ChatbotController
- **Location**: `app/Http/Controllers/Api/ChatbotController.php`
- **Methods**:
  - `message(Request $request)` - Handle chat messages with AI integration
  - `conversation(Request $request)` - Create new conversation
  - `conversations(Request $request)` - List user conversations
  - `showConversation($id)` - Get specific conversation with messages
  - `updateConversation(Request $request, $id)` - Update conversation title
  - `destroyConversation($id)` - Delete conversation
- **Features**:
  - Rate limiting (50 messages/hour)
  - Conversation persistence
  - Legal reference integration
  - AI service integration (mock for now)

#### 1.2 Create Conversation Model
- **Location**: `app/Models/ChatbotConversation.php`
- **Fields**: id, user_id, tenant_id, title, created_at, updated_at
- **Relationships**: user, messages (hasMany)

#### 1.3 Create Message Model
- **Location**: `app/Models/ChatbotMessage.php`
- **Fields**: id, conversation_id, role (user/assistant), content, references, created_at
- **Features**: JSON storage for references array

### Phase 2: Calendar Events API Implementation

#### 2.1 Create CalendarController
- **Location**: `app/Http/Controllers/Api/CalendarController.php`
- **Methods**:
  - `events(Request $request)` - Get events for date range
  - `store(Request $request)` - Create new event
  - `update(Request $request, $id)` - Update event
  - `destroy($id)` - Delete event
- **Features**:
  - Support for tasks, hearings, meetings, deadlines
  - Recurring events support
  - Multi-user calendar sharing

#### 2.2 Create CalendarEvent Model
- **Location**: `app/Models/CalendarEvent.php`
- **Fields**: id, tenant_id, title, description, start_date, end_date, type, user_id, is_recurring, recurrence_rule, created_at, updated_at
- **Features**: Recurrence pattern handling

### Phase 3: Notifications API Implementation

#### 3.1 Create NotificationController
- **Location**: `app/Http/Controllers/Api/NotificationController.php`

- **Features**:
  - Real-time notifications (WebSocket ready)

#### 3.2 Create Notification Model
